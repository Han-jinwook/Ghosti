## 1. 💡 도입 배경 및 기획 취지 (`Why — 왜 이렇게 설계했는가?`)

1. **유저의 실제 문서 생태계 (로컬 엑셀 + 구글시트 `.gsheet` · 구글독스 `.gdoc`)**:
   - 많은 유저가 사이트별 계정 정보(ID/PW), 거래처 미수금·정산표, 강연 원고 등을 내 PC의 엑셀(`.xlsx`)뿐만 아니라 **구글시트(`.gsheet`)와 구글독스(`.gdoc`)**에 기록해 두고 씁니다.
   - 그러나 윈도우 탐색기에 장착된 `Google Drive (G:)` 안의 `.gsheet`·`.gdoc` 파일은 실제 본문 텍스트가 아닌 202바이트짜리 JSON 메타데이터(`{"doc_id": "...", "url": "..."}`)만 담고 있어서, 단순 로컬 파일 파서만으로는 시트 안의 셀 내용이나 본문을 검색할 수 없었습니다.
2. **연동 선택창이 전혀 없는 ‘무설정 스마트 모드 (`Zero-Config Smart Mode`)’ + 로컬 구글 세션 활용**:
   - 유저에게 *"구글 계정을 연동하시겠습니까?"* 같은 설정 팝업이나 OAuth 권한 승인 창을 띄우면 피로감과 진입장벽이 생깁니다.
   - 이미 유저의 윈도우 탐색기에 `G:` 드라이브(`Google Drive`)가 마운트되어 있고 로컬 크롬/엣지 브라우저 및 `Google DriveFS`에 구글 로그인 세션이 연결되어 있으므로, **멀린 Z 코어가 이 로컬 구글 세션을 활용해 단 한 번의 팝업도 없이 백그라운드에서 모든 `.gsheet`(표 셀 데이터)와 `.gdoc`(본문 텍스트)를 조용히 읽어와 로컬 `[스마트 서류함]`에 자동 색인**합니다.

## 2. ⚡ 멀린님 최종 확정 4대 핵심 구현 규칙

1. **탐색기 장착 클라우드 드라이브(`G:\` 등) 무설정 자동 감지 (`Zero-Popup`)**:
   - 유저에게 연동 여부를 묻는 모달/선택창을 일절 띄우지 않고, 로컬 코어가 파일 시스템에 마운트된 `G:\내 드라이브`(및 `Google DriveFS`, OneDrive, MYBOX 동기화 폴더)를 자동으로 감지하여 `[스마트 서류함]` 기본 스캔 경로에 포함합니다.
2. **특정 시트 제한 없이 ‘내 모든 구글독스(`.gdoc`)·구글시트(`.gsheet`) 전체’ 본문·셀 색인**:
   - 문서 1,000개의 텍스트를 모두 합쳐도 10~20MB 미만으로 가벼우므로, 계정 정보 시트에만 국한하지 않고 **`G:` 드라이브 내의 모든 `.gsheet`·`.gdoc` 전체**를 색인합니다.
   - 검색 결과 카드를 클릭하면 `.gsheet`/`.gdoc` 내부의 `url`을 통해 즉시 해당 구글시트/구글독스 웹 화면을 열어줍니다.
3. **계정·비밀번호(`ID/PW`) 화면 표시 규칙 — 로컬 열람이므로 마스킹(`••••`) 없이 원문 노출 + 텍스트 옆 인라인 복사 이모지(`📋`)**:

4. **프라이버시 보안 가드 (TTS 비번 낭독 금지 & 외부 AI 바톤터치 제외)**:
