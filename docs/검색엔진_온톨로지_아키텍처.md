## 1. 핵심 설계 철학 및 아키텍처 전환 배경

### 🚨 기존 방식의 문제점 (절대 회귀 금지 사항)
1. **순수 벡터 유사도(Cosine Similarity) 단독 사용의 한계:**
   - 로컬 `EmbeddingGemma 2` (`onnx-community/embeddinggemma-2-ONNX`, 768차원)의 코사인 유사도는 **방향성이 없는 대칭 함수($A \cdot B = B \cdot A$)**입니다.
   - 따라서 벡터 거리만으로는 `"술" ↔ "맥주"(0.76)`와 `"맥주" ↔ "와인"(0.75)`, `"수영복" ↔ "원피스"(0.74)`의 **상·하위 포함 관계(누가 부모이고 누가 자식인지)**를 구분하지 못합니다.
2. **검색 시점(Query-time) 수동 정규식 그룹 묶기의 한계:**
   - 검색 코드(`vite.config.ts`)에서 `[불쇼, 공연, 축제]`나 `[술, 맥주, 와인]`, `[옷, 수영복, 원피스]`를 평면 그룹으로 묶으면, 사용자가 구체적인 하위어(`"불쇼"`, `"맥주"`, `"수영복"`)를 검색했을 때 형제·상위 개념 사진(`박물관 공연`, `와인`, `원피스`)이 함께 딸려 나오는 **연쇄 오탐(False Positive)**이 발생합니다.
3. **부분합(`OR`) 폴백의 함정:**
   - `"청라 보트"`처럼 실제 사진첩에 존재하지 않는 복합 조건 검색 시, 교집합(`AND`) 결과가 0장이라고 해서 부분 매칭(`OR`)이나 단순 벡터 상위 점수를 반환하면 엉뚱한 사진이 쏟아져 유저 신뢰를 잃습니다.

### ✅ 최종 확립된 정석 아키텍처 (3대 원칙)

```
[사진 인덱싱 시점 (Indexing-Time)]
비전 AI 캡션/키워드 + EXIF GPS 지명
   │
   ▼  (poc/build_korean_photo_ontology.mjs)
표준 한국어 시각 개념 족보 트리 (src/data/koreanPhotoOntology.json)
   ├─ 구체어(triggers) 검출 시 ➔ 1:1 동의어(equivalents) + 상위 부모 개념(parents, Is-A 관계)만 사진에 단방향 상속!
   ├─ 시각 필드(primaryTag, keywordsKo, caption)와 지리 필드(EXIF GPS) 분리 스캔 (지명이 시각 사물 오염 방지)
   └─ 한국어 부분 문자열 착시 차단 (blockWords: '튜브'≠'유튜브', '아이'≠'아이콘', '다리'≠'사다리', '고기'≠'물고기')
   │
   ▼
통합 시맨틱 인덱스 저장 (poc/results/corpus_550_semantic_index.json)
   - ontologyPrimaryTags (핵심 주제 태그 + 상속된 부모 개념어 + 1글자 뿌리 명사)
   - ontologyCaptionTags (배경 캡션 태그 + 상속된 부모 개념어)
   - vec (768차원 EmbeddingGemma 2 정규화 벡터)
```

```
[실시간 검색 시점 (Query-Time: vite.config.ts)]
사용자 검색어 입력 (PC 텍스트 또는 모바일 음성)
   │
   ├─ 1) 수동 정규식 유의어 사전 0줄! (Query-time Regex Expansion 완전 제거)
   ├─ 2) 모든 핵심 토큰에 대해 사전 인덱싱된 ontologyPrimaryTags / ontologyCaptionTags 엄격한 AND 교집합 필터링
   │     - 핵심 주제(ontologyPrimaryTags)에서 모든 토큰이 매칭된 사진이 있으면 배경 캡션 매칭(captionOnly) 제외
   │     - 교집합이 0장이면 억지 결과 노출 없이 즉시 0장 반환 (예: "청라 보트" ➔ 0장)
   └─ 3) 교집합 통과 사진들을 대상으로 768차원 EmbeddingGemma 2 코사인 유사도 + 어휘 가점 합산 정렬
```

## 3. 대표 검색어 검증 기준표 (Regression Test Baseline)

검색 엔진이나 온톨로지를 수정할 때 반드시 아래 기준표를 통과해야 합니다:

| 구분 | 검색어 | 기대 매칭 수 | 검증 포인트 (Is-A 단방향 계층 및 교집합 검증) |
| :--- | :--- | :---: | :--- |
| **1글자 / 하위어** | `"불"` / `"불쇼"` | **10장** | `#공연·불쇼`(10장)만 정확히 나오고 박물관 공연이나 축제 현수막이 섞이지 않아야 함 |
| **상위어** | `"공연"` | **12장** | 상위어이므로 `#공연·불쇼`(10장) + `#공연·축제`(박물관 공연 2장)가 모두 나와야 함 |
| **하위어 vs 상위어** | `"맥주"` / `"와인"` / `"술"` | **8장 / 3장 / 23장** | `"맥주"` 검색 시 와인이 안 섞이고, `"와인"` 검색 시 맥주가 안 섞이며, `"술"` 검색 시 맥주+와인+칵테일(23장) 모두 노출 |
| **하위어 vs 상위어** | `"수영복"` / `"원피스"` / `"옷"` | **50장 / 9장 / 76장** | `"수영복"`과 `"원피스"`는 서로 섞이지 않고, 상위어 `"옷"` 검색 시 모든 의류 노출 |
| **부분 문자열 방어** | `"구명조끼"` / `"문자"` | **7장 / 1장** | `"튜브"`가 `"유튜브"` 알림창에 매칭되거나 `"아이"`가 `"아이콘"`에 매칭되지 않아야 함 |
| **지명 상·하위어** | `"청라"` / `"인천"` | **34장 / 44장** | `"청라"`는 청라 사진만, 상위 지명 `"인천"`은 `청라 + 부평 + 인천공항/영종도` 모두 노출 |
| **없는 조합 (AND)** | `"청라 보트"` | **0장** | 청라(34장)와 보트(68장)의 교집합이 없으므로 반드시 **0장**이어야 함 (`OR` 폴백 금지) |
| **있는 조합 (AND)** | `"코타키나발루 보트"` | **68장** | 코타키나발루 해변/보트 교집합 정확히 반환 |

## 4. 입력 규칙 ✅

### 4.1 Task Prefix (텍스트에만 적용)
- 검색 질의: `task: search result | query: {질의}`
- 문서: `title: {제목 또는 none} | text: {내용}`
- 이미지·영상·오디오에는 prefix를 붙이지 않음.
- 공식 설명: prefix를 빼도 **동작은 하지만 정밀도가 떨어짐.**

### 4.2 토큰 비용 (공유 8,192 토큰)

| 모달리티 | 토큰 비용 | 최대 입력 |
|---|---|---|
| 텍스트 | 서브워드당 1 | 8,192 |
| 이미지 | 장당 280 (기본값) | 약 29장 |
| 영상 | 프레임당 140 (기본값) | 약 58프레임 |
| 오디오 | 초당 25 | 약 327초 |

- **비전 토큰 예산:** 이미지 프로세서의 `max_soft_tokens`를 70 / 140 / 280 / 560 / 1120 중에서 선택. 높을수록 세밀하게 인식하지만 느림. → **PoC 측정 변수**
- **영상:** 기본 1fps로 샘플링하고, 32프레임을 넘으면 균등하게 32프레임으로 줄임.
- **오디오:** 모노 16kHz 입력.

### 4.3 WebGPU 제약
- **배치 1회당 총 토큰을 약 2,700 이하로 유지해야 함.** 넘으면 ONNX Runtime WebGPU 커널이 GPU 디스패치 한도를 초과함. 기본 예산(280)으로 이미지를 배치하면 **한 번에 약 9장이 한계.**
- 여러 이미지를 각각 임베딩하려면 `processor(null, [[img1], [img2]])` 형태로 넘김. 평탄한 리스트로 넘기면 여러 장이 하나의 입력으로 합쳐짐.

1. **왜 단순 파일 크기(Byte)나 MD5 해시가 아닌 `64-bit dHash` + `EXIF` 이중 검증인가?**

2. **진짜 원본 자동 교체 안전핀 (`EXIF` 촬영 메타데이터 + 실제 픽셀 해상도 `width × height`):**
   - `[사진 공유]` 방에 동일 `dHash` 사진이 새로 들어왔을 때, 단순 파일 바이트가 크다고 덮어쓰지 않고 반드시 **① `EXIF 촬영 원본 메타데이터(DateTimeOriginal, Make/Model)`가 살아있고, ② 실제 픽셀 해상도(`width × height`)가 기존 사진보다 더 클 때만** 기존 댓글·좋아요를 100% 보존한 채 고화질 원본으로 무언 교체(Silent Upgrade)합니다.
