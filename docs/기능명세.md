## 1. 코어 검색 엔진 아키텍처 (`vite.config.ts` — `runHybridCorpusSearch`)

### 1.1 검색 파이프라인 구조 (Zero-Regex + Ontology Inheritance + 768D Vector)
현재 검색 엔진은 검색 시점(Query-time)의 수동 유의어 정규식 확장을 완전히 배제하고, **인덱싱 시점의 온톨로지 상향 상속 + 엄격한 `AND` 교집합 + 768차원 EmbeddingGemma 2 코사인 유사도** 3단 결합으로 동작합니다.

1. **한국어 토크나이저 및 조사/어미 분리 (`stripKoParticle`)**
   - 입력 쿼리에서 문장부호를 제거하고 공백 단위로 분리합니다.
   - `바닷가`, `창가`, `물가`, `휴가`, `아이`, `어린이`, `고양이`, `멍멍이`, `물놀이`, `목걸이`, `귀걸이`, `종로`, `을지로`, `다리`, `나무다리`, `선풍기`, `비행기` 등 끝글자가 조사와 겹치는 명사(`KEEP_NOUNS`)를 보호한 뒤, 한국어 조사(`에서, 으로, 이랑, 하고, 부터, 까지, 들, 의, 을, 를, 은, 는, 에, 와, 과, 도`)를 제거하여 어근 토큰을 추출합니다.
   - 수식어/불용어(`SOFT_WORDS`: `사진, 찾아줘, 보여줘, 예쁜, 신나는, 뛰노는` 등)와 핵심 개념 토큰(`hardTokens`)을 분리합니다.

2. **한국어 부분 문자열 착시 차단 (`BLOCK_SUBSTRING_MAP`)**
   - 짧은 한국어 명사가 전혀 다른 복합어의 부분 문자열로 오탐되는 현상을 정규식 마스킹으로 원천 차단합니다.
     - `튜브` 검색 시 ➔ `유튜브`, `자외선램프`, `uv-b` 마스킹 제거
     - `아이` 검색 시 ➔ `아이콘, 아이폰, 아이패드, 아이디어, 아이템, 아이돌, 아이스, 아이라인` 마스킹 제거
     - `다리` 검색 시 ➔ `기다리, 사다리, 책상다리, 식탁다리` 마스킹 제거
     - `모자` 검색 시 ➔ `모자이크` 마스킹 제거
     - `고기` 검색 시 ➔ `물고기` 마스킹 제거
     - `불` 검색 시 ➔ `불안, 불편, 불가, 불구, 불빛` 마스킹 제거

3. **1글자 한국어 명사 및 다자간 토큰 대조**
   - 1글자 명사(`불, 물, 술, 밥, 차, 배, 산, 숲, 밤, 해, 눈, 비, 꽃, 집, 방, 길, 옷, 컵, 잔, 병, 탑, 섬, 강, 창, 문, 책, 글, 개` 등)는 사진의 `ontologyPrimaryTags` / `ontologyCaptionTags`에 독립 원소로 등록되어 있어 $O(1)$ 해시셋(`Set.has`)으로 즉시 매칭되며, 온톨로지 밖의 1글자도 어절 경계 정규식(`singleCharRegex`)으로 검증합니다.
   - 띄어쓰기 복합어(예: `"나무 다리"` ➔ `"나무다리"`, `"조립 설명서"` ➔ `"조립설명서"`)가 하나의 단어로 존재하는 경우 `compoundHit` 가점을 부여합니다.

4. **엄격한 `AND` 교집합 및 핵심 주제(`Tag`) 우선 원칙**
   - 모든 검색 토큰(`queryTokens`)이 빠짐없이 매칭된 사진만 통과합니다 (`matchedGroupCount >= requiredGroupCount`).
   - **부분합(`OR`) 폴백 금지:** 교집합 결과가 0장이면 억지 결과를 보여주지 않고 즉시 `0장`을 반환합니다 (예: `"청라 보트"` ➔ `0장`).
   - **핵심 주제 우선 필터 (`strictTagMatches`):** 모든 검색어가 사진의 핵심 주제(`ontologyPrimaryTags` / `primaryTag` / `keywordsKo` / `location`)에서 매칭된 사진이 1장 이상 존재하면, 배경 캡션에만 스치듯 언급된 사진(`captionOnly`)을 제외하고 핵심 주제 사진만 반환합니다.

5. **768차원 EmbeddingGemma 2 실시간 쿼리 임베딩 및 캐싱 (`embedQueryVector768`)**
   - 로컬 ONNX 런타임(`@huggingface/transformers`)을 통해 `onnx-community/embeddinggemma-2-ONNX` (`q4` 양자화) 모델을 구동합니다.
   - 쿼리를 `task: search result | query: {검색어}` 포맷으로 토크나이징한 뒤 768차원 L2 정규화 벡터를 추출합니다.
   - `queryVecCache` (`Map<string, number[]>`)를 통해 동일 검색어 재요청 시 `0ms` 만에 벡터를 반환합니다.
   - 최종 점수는 `totalScore = vecSim(768차원 내적) + min(0.85, lexicalScore)`로 산출되어 정렬됩니다.

## 2. 한국어 시각 개념 족보 트리 및 인덱서 (`src/data/koreanPhotoOntology.json`, `poc/build_korean_photo_ontology.mjs`)

### 2.1 온톨로지 데이터 구조 (`src/data/koreanPhotoOntology.json`)
- **기반 데이터셋:** Open Multilingual WordNet (OMW-ko) + Google Open Images V7 시각 계층 + 한국인 일상 갤러리 빈출 어휘 + 행정구역 지명 계층 (현재 71개 계층 노드, 약 700개 어휘 수록).
- **노드 스키마:**
  - `id`: 계층 식별자 (예: `alcohol.beer`, `alcohol.wine`, `clothing.swimwear`, `activity.fire_show`, `geo.incheon_cheongna`)
  - `category`: 도메인 (`beverage`, `food`, `clothing`, `people`, `animal`, `nature`, `vehicle`, `place`, `activity`, `document`, `object`, `location`)
  - `triggers`: 사진 캡션/키워드/태그에서 검출할 구체 단어 목록
  - `equivalents`: 100% 동일한 뜻의 1:1 동의어 (예: `['개', '강아지', '반려견', '애완견', '멍멍이', '강쥐', 'dog', 'puppy']`)
  - `parents`: **`Is-A`("A는 B의 일종이다") 단방향 상위 부모 개념어** 및 1글자 뿌리 명사 (예: `맥주` ➔ `['술', '주류', '음료', '술자리', '잔', '컵']`)
  - `blockWords`: 인덱싱 시 부분 문자열 착시를 일으키는 제외 단어 목록

### 2.2 인덱싱 시점 상·하위어 자동 상속기 (`poc/build_korean_photo_ontology.mjs`)
- **시각 필드 vs 지리 필드 분리 스캔:**
  - 일반 시각 사물/활동 노드(`category !== 'location'`)는 오직 시각 필드(`primaryTag`, `keywordsKo`, `captionKo`, `captionEn`)만 스캔합니다. (이를 통해 코타키나발루 GPS 지명에 포함된 `'사피섬'`, `'수트라하버'` 때문에 식당 사진에 `'섬'`이나 `'호텔'` 태그가 붙는 오염을 원천 차단합니다.)
  - 지리 노드(`category === 'location'`)는 EXIF GPS 지명 필드(`locationTag`, `locationKo`, `locationKeywords`)까지 함께 스캔하여 상위 행정구역(`청라 ➔ 서구, 인천, 수도권`, `여의도 ➔ 영등포, 한강, 서울, 수도권`, `속초 ➔ 강원도, 동해`)을 자동 상속합니다.
- **산출물 (`poc/results/corpus_550_semantic_index.json`):**
  - 550장 각 사진 객체에 `ontologyPrimaryTags: string[]` (핵심 주제 + 상속 부모어)와 `ontologyCaptionTags: string[]` (세부 묘사 + 상속 부모어)를 영구 저장합니다.

  - **경기도 고양 (`#고양·삼송`):** 고양시 덕양구 삼송동/일산

## 4. 초저지연 모바일/PC 하이브리드 음성 검색 (`src/services/aiEngine.ts`)

### 4.1 실시간 마이크 캡처 및 모바일 비프음 연동 (`HybridVoiceSession`)
- **병렬 캡처 구조:**
  1. `navigator.mediaDevices.getUserMedia` 오디오 스트림 확보
  2. `AudioContext` + `AnalyserNode`(`fftSize = 64`)로 16밴드 실시간 음성 파형 진폭(`onAmplitude`) 렌더링
  3. 브라우저 내장 `SpeechRecognition` / `webkitSpeechRecognition` (`ko-KR`, `continuous = false`, `interimResults = true`) 병렬 구동
  4. 모바일 호환 `MediaRecorder` (`audio/webm;codecs=opus`, `audio/mp4` 등 자동 감지) 청크 캡처
- **비프음 직후 `0.04초` 자동 종료 (`triggerFastAutoStop`):**
  - 모바일 안드로이드에서 발화 종료 비프음이 울리며 `lastResult.isFinal === true`가 되는 순간, `40ms` 타이머로 즉시 녹음을 자동 종료하고 검색을 트리거합니다 (`onspeechend`, `onend` 이벤트 이중 감지).
  - `stop()` 호출 시 이미 `this.sttTranscript`가 확보되어 있으면 추가 대기(`0ms`) 없이 즉시 반환합니다.

### 4.2 무오디오 패킷 패스트트랙 (`executeZeroSttVoiceSearch`)
- 브라우저 STT(`existingStt`)가 이미 텍스트를 인식한 경우, 수백 KB의 오디오 Blob을 Base64로 인코딩하여 원격 터널(`/__search/voice`)로 업로드하는 과정을 **완전 생략**하고, 즉시 `/__search/query`로 50바이트 텍스트 JSON만 전송합니다.
- 브라우저 STT가 지원되지 않거나 실패하여 `existingStt`가 비어 있는 경우에만 `/__search/voice` 엔드포인트로 오디오 Base64를 전송하며, 서버(`vite.config.ts` — `transcribeAudioToKoreanQuery`)가 Gemini Flash 오디오 멀티모달 인식으로 한국어 쿼리를 추출한 뒤 검색 결과를 반환합니다.

## 5. 물리·광학 교차 검증 엔진 및 클리어몬스터 격리 시스템 (`vite.config.ts`, `src/services/aiEngine.ts`)

### 5.1 100% 실제 픽셀·광학 감사 엔진 (`computeSinglePhotoAudit`, `/__photos/physical-audit`)
모든 사진에 대해 `sharp`를 사용하여 64x64 그레이스케일 및 RGB 픽셀 버퍼를 추출하고 다음 물리 수치를 계산하여 `poc/results/corpus_550_physical_audit.json`에 캐싱합니다 (신규 사진 추가 시 자동 증분 연산):
1. **완전 동일 및 유사 중복 검출 (`md5`, `dhash`):**
   - 파일 바이너리 MD5 해시 및 9x8 그레이스케일 인접 픽셀 비교를 통한 **64-bit Perceptual dHash** 계산.
   - 해밍 거리(Hamming Distance) $\le 8$ 및 촬영 시간차 기반 중복/연사 사본 클러스터링 수행 (파일명 `(0)`, `(1)` 사본 접미사 우선 감지 및 원본 1장 보존 보장).
2. **흔들림·초점 블러 검출 (`maxCellLap`, `meanCellLap`):**
   - 4x4 격자(16개 셀)별 2차 미분 라플라시안 분산(Laplacian Variance: $|4c - l - r - t - b|$)을 계산하여 배경 아웃포커싱(보케) 사진은 보호하고 전체 셀의 초점이 무너진 진짜 흔들린 사진만 판별.
3. **빛번짐·노출 불량 및 스크린샷/문서 판별 (`avgBrightness`, `edgeDensity`, `hasExif`, `wmRatio`):**
   - 평균 휘도(`avgBrightness`), 소벨 엣지 밀도(`edgeDensity`), EXIF 카메라 메타데이터 유무(`hasExif`), 하단 워터마크/타임스탬프 비율(`wmRatio`), 상단 채도/피부톤/하늘/녹지 비율(`skinPct`, `skyPct`, `greenPct`)을 교차 검증하여 인물·여행 사진 오탐을 차단.

### 5.2 안전 격리 보관함 (Quarantine Vault) API
- `POST /__photos/quarantine`: 선택된 사진을 즉시 삭제하지 않고 `d:\SaySee\test_photos_quarantine` 폴더로 물리적 이동(격리)합니다.
- `POST /__photos/restore`: 격리 보관함의 사진을 원래 `d:\SaySee\test_photos` 폴더로 즉시 복원합니다.
- `POST /__photos/delete-permanent`: 격리 보관함 내에서 사용자가 최종 확인한 파일만 영구 삭제(`fs.unlinkSync`)합니다.

## 6. 온보딩 고립 프롬프트 & 지능적 스무고개 라우팅 백엔드 (`vite.config.ts`, `src/services/aiEngine.ts`)

*(현재 UI에서는 대표님 지시에 따라 기본 검색 테스트 집중을 위해 숨김/보류 처리되어 있으나, 백엔드 API 및 엔진 로직은 구현되어 있음)*

1. **온보딩 사진별 고립 프롬프트 API (`POST /__ai/onboarding-prompts`):**
   - 검출된 대표 사진들의 촬영 날짜(`date`), 핵심 키워드(`keywords`), 팩트 캡션(`caption`)을 사진별 독립 번호로 격리하여 Gemini API(`callGeminiFlash`)에 전달, 서로 다른 사진의 장소와 사물이 섞이지 않은(짬뽕 방지) 자연스러운 한국어 검색 제안 문장을 생성합니다.
2. **스무고개(티키타카) 동적 LLM 인터뷰 API (`POST /__ai/tikitaka-interview`):**
   - 검색 결과가 과다하거나 모호할 때, 현재 후보 사진들의 연도·장소·주요 태그 통계 요약본과 대화 히스토리를 바탕으로 `"시간대(연도/계절) ➔ 장소/공간 ➔ 구체적 상황"` 순서의 1문장 질문과 선택지(`quickReplies`), 필터 키워드(`narrowedKeywords`)를 JSON으로 생성합니다.
3. **일일 합산 하이패스 과금 정산 스토어 (`useSaySeeStore.ts`):**
   - 스무고개 대화 도중에는 코인 차감 팝업을 띄우지 않고 `pendingDailySessionCoins` 및 `pendingDailyTurnCount`에만 누적하며, `settleDailyTikiTakaCoins()` 호출 시 일일 마감 1건의 통합 로그(`settledDailyLogs`)로 일괄 정산합니다.
