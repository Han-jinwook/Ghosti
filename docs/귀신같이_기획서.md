## 1. 프로젝트 개요 (Executive Summary)

- **제품명:** Z-Eye (귀신같이) — "말하고(Say) 본다(See)"
- **포지셔닝:** 서버 클라우드 의존 없이, 말 한마디로 내 폰과 PC의 사진을 0.1초 만에 찾아내는 **'초고속 로컬 스나이퍼'** 유틸리티.
- **생태계 역할:** 멀린 허브(Merlin Hub) 패밀리앱 라인업의 **2호 트래픽 마중물 앱**이자, 향후 프로페셔널 사진 큐레이션 툴(**Bes2**)로 파워 유저를 연결하는 브릿지.
- **핵심 가치:**
  1. 100% 프라이버시 (No Upload)
  2. 서버 비용 0원 (무한 마진)
  3. 압도적인 검색 속도
- **개발 원칙:** 결제·인증은 멀린 허브가 담당. 귀신같이는 **검색과 파일 처리(Core Feature)에 200% 집중.**

## 2. 시장 배경 및 타겟 기회 (Blue Ocean Strategy)

- **빅테크의 자충수:** 구글 포토 'Ask Photos' 도입 이후 느려진 검색 속도, AI의 주관적 결과 제한, 프라이버시 침해 우려로 영미권 커뮤니티(Reddit, Hacker News)를 중심으로 불만이 폭발 중.
- **사용자 페인포인트:** 클라우드 스토리지(Google One 등) 구독료 피로도, 모바일 기기 용량 부족(Bloat).
- **귀신같이의 돌파구:** 무거운 원본 백업은 기존 클라우드에 맡기고, 귀신같이는 오직 **'가벼운 썸네일 검색'** 과 **'쓰레기 사진 정리'** 에만 집중 → 클라우드 구독료를 아껴주는 **상호 보완적 킬러 앱**으로 포지셔닝.

## 3. 핵심 UX 및 주요 기능 (Core Features)

### 3.1 음성 주도 스나이핑 (Speech-to-Search) — *D-17, D-20*
- **1차 MVP 전면 탑재 (D-17):** EmbeddingGemma 2 **오디오 인코더**로 음성 파형을 직접 벡터화 → STT 없이 사진 매칭 (Zero-STT, 100% 온디바이스, 음성 데이터의 외부 전송 없음).
- 화면 중앙의 대형 마이크 버튼 + 음성 파형 비주얼.
- "파란 옷 입고 바닷가에서 뛰노는 아이" 등 음성/자연어 질의를 **0.5초 이내(텍스트 0.06초)** 만에 시각적 결과로 매칭.
- **스마트 폴백 (D-20):** WebGPU/메모리 부족 기기만 브라우저 내장 **Web Speech API(STT) → 텍스트 인코더**로 자동 전환하여 100% 실행 보장.

### 3.2 2차 연관 꼬리물기 탐색 (Contextual Tabs)
결과 사진 클릭 시 아래 탭을 자동 생성:
- `[📅 이 날 찍은 사진 전체]` — EXIF 촬영 시각 그룹핑
- `[🐶 비슷한 피사체 사진]` — 이미지↔이미지 벡터 매칭 (동일 EmbeddingGemma 2 벡터 공간)
- `[➕ 2차 자연어 좁혀가기]` — 현재 결과 집합 내 재검색 (Drill-down)

### 3.3 스마트 사진 다이어트 (Trash Cleaner) — *D-03, D-10*
- 스크린샷, 흔들린 사진, 영수증 등을 **0.85 이상의 유사도**로 자동 분류 → 검토 화면.
- 유저 확인 후 **PC 앱이 해당 파일을 원본 폴더에서 `OS 기본 [휴지통]`(`Win32 FOF_ALLOWUNDO`)으로 안전 이동 (`[↩️ 1초 실행 취소]` 지원).**
- 유저는 나중에 OS 기본 `[휴지통]`에서 확인하거나 하단 **`[↩️ 1초 실행 취소(Undo)]`**로 1초 만에 즉시 복원 → API 권한·클라우드 정책과 무관하고 가장 안전하며 직관적.
- 모바일에서는 **정리 예약(Queue)** 만 하고, 실제 이동은 PC 앱이 다음 동기화 때 수행.
- 판별 정확도는 PoC에서 확인. 임베딩만으로 부족하면 휴리스틱(선명도·밝기·해상도·파일명 패턴) 병행 검토.

### 3.4 모바일 온보딩 아하 모먼트 — *D-04, D-08*
1. 첫 실행 온보딩 화면에 **[사진 300장 묶어 가져오기]** 버튼.
2. 폰 사진 선택창에서 유저가 스와이프로 최대 300장 선택 → 완료.
3. **색인 진행 화면:** 진행률(n/300), 예상 남은 시간, "잠시만 기다려 주세요" 안내. 화면 이탈 대비 완료 알림.
4. **300장 100% 색인 완료 후에만 검색 오픈** (점진 공개 없음).
5. 완료 즉시 **비전 인코더를 메모리에서 해제**하고 텍스트 인코더만 유지.
6. "바다에서 강아지랑" 음성 질의 → 0.1초 결과 → **PC 버전 설치 유도** ("나머지 1만 장은 PC에서 한 번에").

### 3.5 PC-모바일 하이브리드 브릿지 — *D-05*
- PC에서 원본 폴더를 스캔해 **초경량 WebP 썸네일(장당 ~15KB)** 과 **벡터**만 생성.
- 폰에는 원본 없이 썸네일 + 인덱스만 동기화 → 용량 걱정 없이 **1만 장 즉시 탐색**.
- **동기화 경로:**
  - **기본값 (대중성):** Supabase 경유 자동 동기화 → 언제 어디서나 끊김 없는 검색.
  - **보안 옵션 (필수 제공):** 설정 `[🔒 로컬 WiFi로만 동기화 (클라우드 무업로드)]` 스위치 → 같은 네트워크에서 PC↔폰 직접 전송.

## 4. 기술 아키텍처 (Tech Stack & AI Engine)

### 4.1 프론트엔드 및 인프라
- **앱 형태:** 모바일/PC **PWA** (manifest.json + Service Worker)
- **프레임워크:** **Vite + React + TypeScript** (D-12)
- **스타일:** Tailwind CSS (Stitch 디자인 토큰 이식)
- **상태/저장소:** Zustand, IndexedDB(idb) / OPFS (Origin Private File System)
- **AI 런타임:** Transformers.js (`@huggingface/transformers`, ONNX) + WebGPU (WASM 폴백)
- **Supabase:** 메타데이터·썸네일·벡터 동기화 저장소 (인증은 Merlin 토큰 기반, 1차는 Mock)

1. **로컬 폴더 워처/스캐너:** 로컬 사진 폴더(구글 드라이브 PC 동기화, MYBOX 동기화 폴더 등)를 드래그&드롭. 전체 업로드 없이 File System Access API로 로컬 읽기 (Chrome/Edge).
2. **로컬 배치 비전 인덱싱:** WebP 썸네일 추출 → WebGPU 백그라운드 배치로 임베딩 생성 → Supabase 또는 로컬 WiFi로 모바일 동기화.
3. **클린몬스터 정리함(OS 기본 휴지통 직행) 처리:** 모바일 정리 예약 큐 수신 → 원본 파일을 `OS 기본 [휴지통]`(`Win32 FOF_ALLOWUNDO`)으로 안전 이동.

### 12.1 인덱싱 성능 실측 요약

| 지표 | 초기 세팅 (스모크) | 최적화 후 (300장 벤치) | 최종 전수 (550장 벤치) | 비고 |

### 12.2 OPFS 영구 캐싱 실측
- **최초 다운로드 (Cold Load):** 17.9초 소요 (총 296MB 네트워크 전송, 브라우저 OPFS에 자동 기록)
- **재실행 시 로드 (Warm Load):** **3.7초 ~ 4.2초** (네트워크 전송 **0MB**, 로컬 OPFS 직접 로딩)
- **디스크 점유량:** 텍스트+비전+오디오 q4 전체 16개 파일 기준 약 **727MB** (브라우저 스토리지 쿼터 11.4GB 중 6.3%로 여유)
- **`navigator.storage.persist()`:** 브라우저 캐시 자동 삭제 방지 등록 완료

### 12.3 오디오 직접 검색 (Zero-STT Audio ➔ Photo Vector) 실측
음성 파형을 STT 텍스트 변환 없이 EmbeddingGemma 2 오디오 인코더로 직접 768차원 임베딩한 결과:

1. **지연 시간 (Latency):**

### 12.5 다이어트(클린몬스터 정리함(OS 기본 휴지통 직행)) 오탐 버그 분석 및 3단계 하이브리드 물리+AI 필터 적용 (2026-10-15 긴급 패치)
Phase 1 초기 구동 시 일반 가족/인물 사진이 `OS 기본 [휴지통]`(`Win32 FOF_ALLOWUNDO`)에서 `영수증 • 90.8%`, `스마트폰 • 95.6%`, `흔들리고 • 90.8%`로 오분류되는 현상이 발견되어 전수 조사 및 즉각 패치를 완료함.

1. **원인 #1 — 상위 10위 무조건 강제 편입 및 가짜 신뢰도 수식 버그 (`aiEngine.ts`):**
   - 기존 코드가 `screenshot_ko`, `receipt_ko`, `blurry_ko`, `document_ko` 검색 결과의 **상위 10개(`rank < 10`)를 무조건 쓰레기 사진으로 강제 분류**하고 `0.86 + (10 - rank) * 0.012`(`87.2% ~ 98.0%`)라는 가짜 퍼센트를 부여함.
   - 실제 폴더 내 스크린샷은 **3장**뿐이었음에도 4~10위에 있던 일반 가족사진 7장이 강제로 `스마트폰 • 95.6%`로 둔갑함.
2. **원인 #2 — 한국어 날짜 워터마크에 의한 허브 벡터(Vector Hubness) 현상:**
   - 2024/2026년 카메라 사진 우측 하단에 찍힌 한글 날짜 스탬프(`2026년 10월 02일 오전 10:30` 등)에 EmbeddingGemma 2의 OCR 성향이 반응하여, 특정 가족사진 6장(`20260926_131245.jpg`, `20261002_103044.jpg`, `20240720_200818.jpg` 등)이 무려 9~11개 한국어 쿼리에서 동시에 코사인 `0.66~0.68`을 받는 **허브 벡터(Hub)**로 작동함.
   - **해결:** 4개 이상의 무관한 쿼리에 중복 출현하는 허브 벡터에 **CSLS(Cross-domain Similarity Local Scaling) 평균 차감 페널티**를 적용하여 무관한 검색어 및 클린몬스터 정리함(OS 기본 휴지통 직행)에서 완전 배제함.
3. **원인 #3 — 기획서 3.3절/딥리서치 1절의 물리적 휴리스틱(Laplacian Variance / EXIF / 중복검출) 결합 적용:**
   - 순수 시맨틱 유사도 단독 판정을 폐기하고 **3단계 물리+AI 하이브리드 필터**로 교체하여 **가족/인물 사진 오탐률 0%** 달성:
     - **스마트폰 스크린샷 (3장):** 파일명(`Screenshot_*`)/모바일 캡처 해상도비 + UI 시맨틱 일치 (`Screenshot_20261014_110205_Messages.jpg` 등 3장 100% 정확 선별)
     - **글씨가 많은 문서·서류·라벨 (6장):** 고대비 인쇄 텍스트 밀도 + 문서 시맨틱 일치 (조립 설명서 `20260814_224330.jpg`, 여권 서류 `20261011_221613.jpg`, 안내 현수막 `20261004_154410.jpg`, 제품 라벨/스펙표 3장)
     - **흔들리고 초점 나간 사진 (5장):** `sharp` 기반 **Laplacian Variance < 350** 광학 블러 실측 통과분만 선별 (`20260815_142557.jpg` 보행 중 바닥 오촬영 `LapVar 130.1`, `20260815_142625.jpg` 모션 블러 등 5장)
     - **영수증·부품메모·중복샷 (11장):** 주차장 기둥 메모(`20260815_131025.jpg` 지하2층 K13), DVI 케이블/볼트/안정기 부품 확인용 접사 5장, `(0).jpg` 중복 저장 사본 5장 등 총 11장 선별
4. **원인 #4 — EXIF 회전값(`orientation: 6, 8, 3`) 자동 보정 및 WebP 고속 썸네일 적용 (`vite.config.ts`):**

### 13.3 Phase 1 집중 구축 3대 코어 (A · B · C)

#### A. 압도적 속도의 오프라인 음성/자연어 검색 + 300장 온보딩 데모

#### B. 지능적 LLM 라우팅 (프리미엄 티키타카 / 스무고개 인터뷰)
- **작동 조건:** 검색 결과가 방대하거나(예: 300장 이상 매칭) 유저의 질문이 모호할 때, **[AI 티키타카 토글 ON]** 상태인 유저에게 지능적으로 개입.
- **스무고개 인터뷰 (2~3턴):** `"시간대(연도/계절) ➔ 장소 ➔ 상황"` 순으로 2~3턴의 짧은 대화를 통해 검색 범위를 압축.
- **JSON 지시서 변환:** 대화로 도출된 단서를 구조화된 **JSON 검색 지시서**(`dateRange`, `visualQuery`, `excludeTrash` 등)로 변환하여 로컬 EmbeddingGemma 2에 전달, 최종 타겟 사진 색출 (**멀린 생태계 통합 코인 종량제 차감**).

#### C. 클린몬스터 Lite (명백한 쓰레기 + 심플 연사/중복 가로 스와이프 Pick)

2. **심플 연사/중복 정리 (Perceptual dHash 탑재 + 가로 스와이프 Pick UI)**

1. **배경 및 B2B 파급력:**
   - 소규모 사업장(SOHO) 및 기업 팀 단위의 유료 클라우드(마이박스, 구글 드라이브 등 인당 월 과금 모델)를 완벽히 대체한다.
   - 상단 전용 배너 타이틀: **`"사무실 PC 폴더를 전 직원의 1초 투시 검색 서버 & 윈도우 탐색기(S:)로 연결합니다"`** (우측에 마스터 PC 온라인 상태 및 접속 중인 팀원 수 실시간 표시).
2. **문서/미디어 듀얼 모드 (`🔍 투시검색 뷰` vs `🗂️ 윈도우 폴더 트리 뷰`):**
   - **`🔍 투시검색 뷰 (기본)`:** 계약서, 견적서, 엑셀 단가표·세금계산서 원장 등의 본문 텍스트와 표(Table) 내용까지 1초 만에 꿰뚫어 보는 시맨틱 검색 화면. **마스터 PC가 오프라인이더라도**, 파일 클릭 시 모바일/외부 PC에 선행 캐싱된 **30KB 분량의 전체 텍스트·표 요약 프리뷰가 0.1초 만에 즉시 열려** 내용을 확인할 수 있다.
   - **`🗂️ 윈도우 폴더 트리 뷰`:** 기존 업무의 레거시 탐색기 사용 습관을 완벽히 유지할 수 있도록, 마스터 PC의 실제 업무 폴더 구조(`S:\`)를 좌측 트리와 우측 파일 리스트로 펼쳐 보여준다.
3. **가상 드라이브 마운트(`S:`) 및 File Lock (동시 편집 충돌 방지):**
   - 화면 우측 상단에 **`[💽 내 PC 윈도우 탐색기에 ‘업무 드라이브(S:)’ 자동 마운트]`** 원클릭 버튼을 배치한다.
   - 팀원 중 누군가 문서를 열어 작업 중일 때는 해당 파일 옆에 **`[🔒 편집 중 (이름)]`** 배지를 띄워 덮어쓰기 충돌을 완벽히 차단한다.

# [제 1 부] 허브 전담 AI 통제 구역 (공통 인프라 & 레이아웃)

이 구역의 원칙들은 멀린 패밀리 생태계의 통일성을 위해 **허브 전담 AI가 직접 각 앱의 코드를 수정하여 배포(통제)**합니다. 개별 앱 AI는 이 구조를 임의로 훼손해서는 안 됩니다.

## 1. SSOT (Single Source of Truth) 원칙
- 유저 식별자(UUID)와 계정 정보, 지갑 정보는 오직 **허브 DB(`family_users`)만이 유일한 진실 공급원**입니다.
- 이메일이나 로컬 닉네임 등을 임의의 보조 수단으로 매핑하여 시스템을 우회하거나 어지럽히는 행위는 절대 금지됩니다.

## 2. 반응형 배너 분기 및 고정 위치 원칙 (`HubResponsiveWing`)
패밀리 앱에서 우측에 배치되는 공유 카드 및 파트너 배너 레이아웃은 허브 SDK(`HubResponsiveWing`)에 의해 통제됩니다.
- **[1120px 이상 (PC/태블릿 가로)]**: 우측 빈 공간에 사이드 윙(`aside`) 형태로 고정 배치합니다. 
- **[1120px 미만 (모바일/화면 축소)]**: 우측 윙을 숨기고, 화면 하단 스티키 배너 및 60초 지연 플로팅 버튼(FAB) 기반의 바텀 시트 팝업으로 대체합니다.

## 3. 공통 UI 중앙화 및 사전 승인 원칙 (충돌 방지)
- PWA 앱 설치 팝업, 전역 로그인 모달 등은 개별 앱 내부에 파편화시키지 않고, **오직 허브 SDK(`merlin-hub-sdk`) 내부에 중앙화**하여 패밀리 앱에 동일하게 전파할 의무를 가집니다.
  - **[HubPWAInstallPrompt 통일]**: 모든 PWA 설치 팝업은 허브 SDK의 `HubPWAInstallPrompt`를 사용해야 합니다. 해당 컴포넌트는 UserAgent 변조(네이버 웨일 사이드바 등)에 대비하여 **화면 가로폭이 768px을 초과하는 PC/데스크톱 환경에서는 절대 노출되지 않도록 하는 강력한 차단 로직**을 내장해야 합니다.
- 단, 개별 앱의 고유한 레이아웃이나 기존 기능과 시각적 충돌이 명확히 예상되는 경우, 허브 AI는 코드를 강제 덮어쓰기 전에 **반드시 사장님(멀린)의 사전 승인을 구한 뒤** 안전하게 적용해야 합니다.

## 4. 모바일 반응형(Mobile-First) UI 기초 공사
웹앱(PWA)이 네이티브 앱처럼 동작하도록 다음 뼈대 원칙을 허브 AI가 공통 레이아웃에 주입합니다.
- 하단 스티키 바나 플로팅 버튼(FAB)에 `pb-[env(safe-area-inset-bottom)]` 적용 (기기 하단 간섭 방지).
- 모바일에서 공유 버튼 등 핵심 액션은 1분 지연 노출(Dynamic Nudge)하여 피로도를 낮춤.

## 5. 헤더 패밀리앱 스위처(F) 고정 배치 원칙
- 헤더 메뉴 및 우측 프로필 위젯 배치 시, 패밀리앱을 상징하는 **'F' 마크(`HubAppSwitcher`)는 반드시 프로필 위젯의 우측(우측 최상단 끝)에 고정 배치**합니다.
- 패밀리 생태계 간 일관된 UI 경험을 위해, 어떠한 경우에도 F 마크를 프로필의 좌측이나 다른 영역에 임의로 배치하여 UI 통일성을 해쳐서는 안 됩니다.

## 6. 모바일 다메뉴(4개 이상) 헤더 네비게이션 표준 규격
모바일 화면(360px~430px)에서 메뉴 탭이 4개 이상일 때의 UI/UX 처리 정책입니다.

1. **[제1원칙: 1줄 핏팅 우선 (Fit-to-Width)]**:
   - 우측 `[🥳F]` 캡슐(약 60px)과 좌측 로고를 제외한 가로 여백(약 220~240px)에 **4개 메뉴 탭(2~3글자 컴팩트 라벨 + `px-2.5`)을 1줄에 완벽 핏팅**하여, 스크롤 자체를 발생시키지 않는 것을 최우선으로 합니다.
2. **[제2원칙: 자동 롤링/루프 절대 금지 (Anti-Marquee)]**:
   - 메뉴 탭이 혼자서 상시 움직이거나(전광판 Marquee) 주기적으로 스크롤되는 것은 **유저가 손가락으로 누르는 순간 엉뚱한 탭이 클릭되는 '치명적 오터치(Mis-tap)'와 심각한 시각 피로도를 유발하므로 절대 금지**합니다.
3. **[제3원칙: 5개 이상 스크롤 발생 시 표준 처리 (Fade Mask & One-time Peek)]**:
   - **우측 페이드 마스크 (`mask-image`)**: 스크롤바는 숨기되, 우측 끝 메뉴가 반쯤 잘려 보이게 은은한 페이드 그라데이션을 주어 "옆에 메뉴가 더 있다"는 것을 본능적으로 인지시킵니다.
   - **최초 진입 1회성 피크 넛지 (One-time Peek Bounce)**: 첫 진입 0.8초 후 우측으로 살짝 30px 슥 움직였다가 제자리로 돌아오는 1회성 가이드 애니메이션을 제공합니다.
   - **선택 탭 자동 중앙 정렬 (`scrollIntoView({ inline: 'center' })`)**: 유저가 탭을 선택하면 해당 탭이 화면 중앙으로 스무스하게 정렬됩니다.

# [제 2 부] 개별 앱 전담 AI 자율 수행 구역 (앱 특화 UX)

아래 원칙들은 개별 패밀리 앱(어그로필터, 뭐먹지 등)을 담당하는 AI가 **해당 앱의 특성과 데이터 구조에 맞게 알아서 자율적으로 구현**해야 하는 지침입니다.

## 5. 상호작용 피드백 및 완전성 원칙 (The Click-Link Rule)
- 프로필, 설정, 취소, 메뉴 등 유저가 클릭/터치할 수 있는 **모든 인터랙티브 요소**에는 마우스 호버 시 반드시 손가락 모양 커서가 나오도록 `cursor-pointer` 클래스를 누락 없이 명시해야 합니다.
- **터치 타겟 및 마이크로 인터랙션**: 모든 클릭 가능한 요소는 44px 이상을 권장하며, 눌렀을 때 즉각적인 피드백(`active:scale-[0.98]`, `active:bg-opacity-80`)을 필수 적용합니다. 텍스트 복사가 불필요한 UI에는 `select-none`을 적용합니다.
- 기능이 연결되지 않은 껍데기 UI('먹통' 상태) 노출 금지 (반드시 Alert/Toast로 미구현 안내).

## 6. 더미 메모 온보딩 (Populated Empty State / Starter Content)
유저가 앱에 처음 진입하여 아무런 데이터가 없을 때(Blank Slate), 텅 빈 화면을 보여주는 것은 최악의 이탈을 유발합니다. 따라서 **조회 전용 페이지가 아닌, 등록(입력) 섹션이 존재하는 모든 페이지에는 무조건 페이지 특성에 맞는 '샘플(목업) 데이터'를 1개씩 만들어두어야 합니다.**
- **동작 방식**: 유저가 앱 사용법을 시각적으로 단번에 파악할 수 있도록 샘플을 노출해두고, **해당 페이지에서 유저가 실제 데이터를 단 1개라도 등록하는 순간 그 페이지의 샘플 데이터는 즉시 수거(영구 Hide)하는 개념**입니다. 전체 데이터가 아닌 철저히 '해당 페이지' 단위로 수거가 이루어져야 합니다.
- **샘플(견본)의 시각적 표시**: 유저가 본인의 데이터로 오인하지 않도록, 앱 담당 AI는 앱의 디자인 성격에 맞춰 다음 두 가지 중 하나의 방식으로 샘플임을 명시해야 합니다.
  - **[A안] 글래스모피즘 리본**: 카드 우측 상단 모서리에 반투명한 대각선 띠(`💡 SAMPLE`)를 두릅니다.
  - **[B안] 하단 페이드아웃 + 툴팁**: 카드 목록의 맨 아래를 그라데이션으로 흐리게 처리(`mask-image: linear-gradient`)하고, "첫 데이터를 입력하면 샘플은 사라져요!" 라는 안내 툴팁을 띄웁니다.

## 7. 모바일 폼 및 숫자 입력창 UX 표준 규격 (Mobile Input & Back-Cursor Rule)
모바일 브라우저에서 숫자, 금액, 수량, 인증번호 입력 시 유저가 겪는 커서 오동작 및 키패드 불편을 원천 방지하기 위해 다음 5대 폼 표준을 준수합니다.

1. **스마트 키패드 & 스핀 버튼 제거 (`inputMode`)**:
   - `type="number"`의 불필요한 증감 화살표(스핀 버튼)와 브라우저별 커서 제약 에러를 피하기 위해, 정수 입력은 `type="text" inputMode="numeric" pattern="[0-9]*"`, 소수점/실수 입력은 `inputMode="decimal"`을 표준으로 사용합니다.
2. **커서 맨 뒤 자동 위치 (Back-Cursor Focus)**:
   - 모바일에서 입력된 기존 숫자를 수정하려고 재터치했을 때 커서가 앞쪽에 걸려 백스페이스(⌫)가 먹통이 되는 현상을 방어하기 위해, SDK 공통 헬퍼인 `handleCursorToEnd`를 `onFocus` 및 `onClick`에 기본 바인딩합니다.
   ```tsx
   import { handleCursorToEnd } from '@/src/services/merlin-hub-sdk/react';

   <input
     type="text"
     inputMode="numeric"
     value={count}
     onFocus={handleCursorToEnd}
     onClick={handleCursorToEnd}
     onChange={(e) => setCount(e.target.value.replace(/[^0-9]/g, ''))}
   />
   ```
3. **인증번호 원터치 자동완성 (`autoComplete="one-time-code"`)**:
   - 6자리 OTP, 문자 인증번호 입력 필드에는 반드시 `autoComplete="one-time-code"`를 지정하여 모바일 키보드 상단 칩을 통한 1초 원터치 완성을 보장합니다.
4. **마이크로 햅틱 피드백 (`triggerHaptic`)**:
   - 폼 입력 완료, 저장 성공, 복사 성공 시 SDK의 `triggerHaptic('light' | 'success')`를 호출하여 네이티브 앱 감성의 가벼운 진동을 제공합니다.

## 8. 검색 UI 최근 검색어(Recent Searches) 및 Zero-Clutter 표준 규격 (모든 앱 디폴트)
사용자가 데이터를 탐색하는 모든 검색 입력창(상품, 부품, 주문, 게시글, 메뉴, 영상 등)은 유저의 반복 검색 피로를 줄이고 모바일/PC 화면 공간을 극대화하기 위해 다음 규격을 디폴트로 적용합니다.

1. **군더더기 텍스트 완전 배제 (Zero-Clutter)**:
   - 검색창 하단에 "검색 결과: 'OOO' (N건)", "검색 초기화" 같은 불필요한 보조 안내선과 여백 낭비 버튼을 나열하지 않습니다.
   - 검색어 확인 및 리셋은 검색 입력창 내부의 텍스트 값 및 우측의 깔끔한 인라인 삭제(`✕`) 버튼 하나로 심플하게 해결합니다.
2. **최근 검색어(Recent Searches) 로컬 자동 영구 누적**:
   - 사용자가 검색창에 검색어를 입력하고 실행(Enter, 선택, focus out 등)하면 `localStorage`에 최근 검색어(최대 6~10개)를 중복 없이 최신순(선두)으로 자동 누적 보관합니다.
3. **입력창 클릭/포커스 시 플로팅 드롭다운 연동**:
   - 검색창 클릭/포커스(`onFocus`) 시 입력창 바로 아래에 플로팅 드롭다운(`absolute z-30`)으로 ⏱️ 최근 검색어 칩 목록이 매끄럽게 딸려나옵니다.
   - **원터치 재검색**: 칩 터치 1번으로 즉시 해당 검색어가 입력창에 주입되고 검색이 실행됩니다.
   - **간결한 관리**: 각 검색어 칩 우측에 개별 삭제(`✕`) 버튼을 제공하고, 드롭다운 우측 상단 또는 하단에 `전체삭제` 버튼을 배치합니다.
   - **자연스러운 닫힘**: 외부 영역 터치/클릭(`onBlur` 또는 바깥 클릭 감지) 시 드롭다운이 자연스럽게 닫히도록 처리합니다.
4. **모바일 가상 키패드 호환 방어**:
   - 모바일 키보드가 올라온 상태에서도 결과 목록이나 드롭다운이 화면을 가리거나 깨지지 않도록 `max-h-48 overflow-y-auto` 및 명확한 `z-index` 계층을 방어합니다.

## 2. 탐색기 장착 `G:` 드라이브(구글 드라이브) 및 모든 구글독스(`.gdoc`)·구글시트(`.gsheet`) '무설정 스마트 모드(Zero-Config)' 통합 투시검색

### ① 도입 배경 및 핵심 기획 취지 (Why)
1. **유저의 실사용 문서 생태계 (로컬 파일 + 모든 구글독스·구글시트)**:
   - 많은 유저가 계정 정보(ID/PW), 거래처 정산표, 원고 등을 로컬 엑셀(`.xlsx`)뿐만 아니라 **구글시트(`.gsheet`)와 구글독스(`.gdoc`)**에 저장합니다.
   - 그런데 윈도우 탐색기에 장착된 `Google Drive (G:)` 안의 `.gsheet`·`.gdoc` 파일은 202바이트짜리 JSON(`{"doc_id": "...", "url": "..."}`)만 담고 있어 단순 로컬 파서만으로는 셀 내용을 읽지 못합니다.
2. **왜 '연동 선택창'을 띄우지 않는 '무설정 스마트 모드(Zero-Config)'인가?**:
   - 이미 탐색기에 `G:` 드라이브가 연결되어 있는데 유저에게 *"구글 계정을 연동하시겠습니까?"*라는 선택창을 또 띄우면 번거롭습니다.
   - 탐색기에 `G:` 드라이브가 감지되면 **선택창 없이 자동으로 `G:` 안의 일반 문서와 모든 `.gsheet`/`.gdoc` 본문·셀 텍스트까지 백그라운드에서 색인**해야 진정한 무설정 투시검색이 완성됩니다.

### ② 구체적 구현 명세
1. **탐색기 장착 클라우드 드라이브(`G:\` 등) 무설정 자동 감지 (Zero-Popup)**:
   - 연동 확인 모달 없이 `G:\내 드라이브`를 자동 감지하여 `[스마트 서류함]` 기본 스캔 경로에 포함합니다.
2. **특정 시트 제한 없이 '내 모든 구글독스(`.gdoc`)·구글시트(`.gsheet`) 전체' 본문·셀 색인**:
   - 문서 1,000개 텍스트도 10~20MB 미만으로 가벼우므로 계정 정보에만 제한하지 않고 **모든 `.gsheet`·`.gdoc` 전체**를 색인합니다.
   - `.gsheet`/`.gdoc` 내부 JSON에서 `doc_id`와 `url`을 파싱한 뒤, 로컬 코어가 백그라운드에서 전체 시트 탭·행(Row)·열(Cell) 텍스트 및 본문을 읽어 로컬 암호화 DB(`[스마트 서류함]`)에 색인합니다.
3. **투시검색 & 음성 브리핑 & 원터치 열기 + 비밀번호 프라이버시 가드**:
   - *"구글시트에 적어둔 넷플릭스 계정 알려줘"*, *"미수금 시트에서 김 사장님 금액 얼마야?"* 등 질의 시 0.1초 만에 찾아내고 카드 클릭 시 해당 구글시트/독스 `url`을 즉시 오픈합니다.
   - 단, 계정/비밀번호 행 조회 시 `[아이디 복사]` / `[비번 복사]` 버튼을 제공하되, **비밀번호(`Password`) 값은 TTS 음성으로 소리 내어 읽지 않으며 외부 AI 자동 바톤터치 대상에서도 제외**합니다.
