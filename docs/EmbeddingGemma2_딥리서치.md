# EmbeddingGemma 2 팩트 시트

> **문서 성격:** 참고용 사실 자료. 외부 LLM 딥리서치의 **의견·결론은 빼고 사실 주장만** 남겼고, 공식 모델 카드와 대조함.
> **최종 갱신:** 2026-10-14
> **공식 출처:** [onnx-community/embeddinggemma-2-ONNX 모델 카드](https://huggingface.co/onnx-community/embeddinggemma-2-ONNX) · [google/embeddinggemma-2](https://huggingface.co/google/embeddinggemma-2)
> **연관 문서:** [SaySee기획서.md](./SaySee기획서.md)
>
> **검증 표시:** ✅ 공식 모델 카드로 확인 · ⚠️ 공식 카드와 다름 · ❔ 딥리서치 주장(출처 미확인) → PoC 실측으로 검증

## 1. 모델 구성 ✅

| 항목 | 값 |
|---|---|
| 개발/라이선스 | Google DeepMind / Apache 2.0 |
| 전체 파라미터 | 740M = 텍스트 270M (백본 130M + 임베더 140M) + 비전 170M + 오디오 300M |
| 출력 | 단일 **768차원** 공유 벡터 공간 (텍스트·이미지·영상·오디오 상호 비교 가능) |
| MRL 절삭 | 512 / 256 / 128차원 (절삭 후 **L2 재정규화 필수**, 질의·문서 차원 일치 필수) |
| 컨텍스트 | 8,192 토큰 |
| 언어 | 100+ 언어 (카드 명시: "언어별 성능이 동일하지 않을 수 있음") |
| 풀링 | Mean Pooling, 512→768 프로젝션 |
| 학습 데이터 컷오프 | 2025년 1월 |

### 1.1 모듈별 선택 로드 ✅
안 쓰는 인코더 설정(`vision_config`, `audio_config`)을 `null`로 만든 뒤 로드하면 해당 인코더를 받지 않음.

| 활성 모달리티 | 유효 크기 |
|---|---|
| 텍스트만 | 270M |
| 텍스트 + 이미지 | 440M |
| 텍스트 + 오디오 | 570M |
| 전체 | 740M |

- 영상 프레임도 비전 인코더를 거침.
- `feature-extraction` 파이프라인을 쓰면 모든 인코더를 로드함 → 선택 로드하려면 `AutoModel` 직접 사용.

## 2. 다운로드 용량 (ONNX, 정밀도별) ✅

| dtype | 텍스트 | 비전 | 오디오 | 합계 | fp32 대비 코사인 유사도 (최악) |
|---|---|---|---|---|---|
| `fp32` | 1085 MB | 671 MB | 1173 MB | 2929 MB | 1 |
| `fp16` | 543 MB | 336 MB | 587 MB | 1465 MB | 0.9998 |
| `q8` | 314 MB | 195 MB | 340 MB | 850 MB | 0.9997 |
| `q4` | **175 MB** | **109 MB** | 189 MB | 473 MB | 0.975 (텍스트 0.988) |
| `q4f16` | 157 MB | 98 MB | 171 MB | 426 MB | 0.975 (텍스트 0.988) |

- 공식 권장: 브라우저 WebGPU에서는 **`q4`**. 품질이 중요하면 `q8` 또는 WebGPU `fp16`.
- 정밀도별로 인코더를 따로 지정할 수 있음. 예: `dtype: { model: "q4", vision_encoder: "q4" }`
- **SaySee 적용 시 (q4 기준):** 모바일 검색용(텍스트만)은 약 175MB, 모바일 온보딩용(텍스트+비전)은 약 284MB.

### 3.1 MRL 차원별 품질 ✅

| 차원 | 압축비 | MTEB 다국어 | MIEB lite | MMEB v2 전체 |
|---|---|---|---|---|
| 768 | 1:1 | 61.36 | 64.64 | 59.01 |
| 512 | 1:1.5 | 61.17 | 64.32 | 58.38 |
| 256 | 1:3 | 60.41 | 63.13 | 56.24 (768 대비 약 95%) |
| 128 | 1:6 | 57.89 | 59.06 | 45.65 (768 대비 약 77%) |

- 공식 설명: 256차원까지는 손실이 거의 없음. 128차원은 멀티모달 품질이 크게 떨어지므로 텍스트 전용 작업에 적합.

## 4. 입력 규칙 ✅

### 4.1 Task Prefix (텍스트에만 적용)
- 검색 질의: `task: search result | query: {질의}`
- 문서: `title: {제목 또는 none} | text: {내용}`
- 이미지·영상·오디오에는 prefix를 붙이지 않음.
- 공식 설명: prefix를 빼도 **동작은 하지만 정밀도가 떨어짐.**

### 4.2 토큰 비용 (공유 8,192 토큰)

| 모달리티 | 토큰 비용 | 최대 입력 |
|---|---|---|
| 텍스트 | 서브워드당 1 | 8,192 |
| 이미지 | 장당 280 (기본값) | 약 29장 |
| 영상 | 프레임당 140 (기본값) | 약 58프레임 |
| 오디오 | 초당 25 | 약 327초 |

- **비전 토큰 예산:** 이미지 프로세서의 `max_soft_tokens`를 70 / 140 / 280 / 560 / 1120 중에서 선택. 높을수록 세밀하게 인식하지만 느림. → **PoC 측정 변수**
- **영상:** 기본 1fps로 샘플링하고, 32프레임을 넘으면 균등하게 32프레임으로 줄임.
- **오디오:** 모노 16kHz 입력.

### 4.3 WebGPU 제약
- **배치 1회당 총 토큰을 약 2,700 이하로 유지해야 함.** 넘으면 ONNX Runtime WebGPU 커널이 GPU 디스패치 한도를 초과함. 기본 예산(280)으로 이미지를 배치하면 **한 번에 약 9장이 한계.**
- 여러 이미지를 각각 임베딩하려면 `processor(null, [[img1], [img2]])` 형태로 넘김. 평탄한 리스트로 넘기면 여러 장이 하나의 입력으로 합쳐짐.

## 5. 딥리서치 주장 대조

| 주장 | 판정 | 비고 |
|---|---|---|
| 텍스트 270M / 비전 170M / 오디오 300M, 768차원 단일 공간 | ✅ | 카드와 일치 |
| MMEB v2 Image 57.28 / VisDoc 67.84 / Video 50.67 | ✅ | 카드와 일치 |
| 영상: 프레임당 140토큰, 최대 약 58프레임, 8,192 컨텍스트 | ✅ | 카드와 일치 (기본 32프레임으로 서브샘플링) |
| MRL 256d에서 약 95% 유지, 128d에서 약 75% | ✅ | MMEB 기준 계산하면 약 95% / 77% |
| 텍스트 쿼리에 task prefix 필요 | ✅ / ⚠️ | 필요한 건 맞음. 다만 카드는 "빼도 동작, 정밀도 저하"라고 해서 "심각하게 훼손"은 과장 |
| fp16 구동 시 NaN 발산, bf16/fp32 필수 | ⚠️ | ONNX 카드는 `fp16`의 코사인 0.9998을 제시하고 WebGPU `fp16`을 권장 옵션으로 명시. PyTorch 체크포인트에만 해당하는 내용일 수 있음 → PoC에서 `fp16`/`q4f16` NaN 여부 확인 |
| 한국어 검색이 1세대보다 하락 (1순위 정답 162건 vs 153건) | ❔ | 출처 미확인 (국내 커뮤니티 테스트라고만 언급). 공식 MTEB 다국어 평균은 2세대가 근소하게 높음(61.36 vs 61.15). → **PoC에서 한국어 질의로 직접 실측** |
| 한국어 512토큰 제한 시 잘림 | ❔ | 사진 검색 질의는 짧아서 영향이 적을 것으로 예상. 확인 필요 |
| 쿼리당 지연 20~70ms (WebGPU) | ❔ | PoC 실측 대상 |
| 기기별 지연 추정 (RTX 3060 / M3 / 모바일) | ❔ | 원문에도 "추정"이라고 적힘. PoC 실측 대상 |
| Pixel 11 Pro 기준 메모리: 텍스트 191MB / 전체 멀티모달 567MB | ❔ | 다운로드 크기(q4: 텍스트 175MB, 텍스트+비전 284MB)와는 다른 지표 → PoC 실측 대상 |
| iOS Safari `maxStorageBufferBindingSize` 128~256MB | ❔ | 기기마다 다름. PoC에서 `adapter.limits`를 출력해 확인 |
| 흐림·어두움 등 품질 판별은 임베딩만으로 약함 | ❔ | PoC에서 정리대기함 판별 정확도로 확인 |
| 작은 텍스트(OCR)와 공간 구도 인식이 약함 | ❔ | PoC 질의 세트에 포함해 확인 |

## 6. PoC 실측 항목 (위 ❔ 항목 검증용)

1. 모델 다운로드·로드 시간 (텍스트만 / 텍스트+비전)
2. 이미지 1장당 임베딩 시간, 300장 총 소요 시간 (PC / 모바일)
3. 텍스트 질의 1건당 임베딩 지연
4. 300장 대상 코사인 검색 지연
5. 메모리 사용량 (가능한 범위: `performance.memory`, `measureUserAgentSpecificMemory`)
6. WebGPU 어댑터 한도 (`maxStorageBufferBindingSize`, `maxBufferSize`)
7. `fp16` / `q4f16` NaN 여부
8. 한국어·영어 질의 검색 품질 (상위 결과 육안 확인)
9. 비전 토큰 예산(70 / 140 / 280)별 속도와 품질
10. 비전 인코더 해제 후 메모리 반환 여부
