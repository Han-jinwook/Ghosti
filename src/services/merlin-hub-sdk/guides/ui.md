# 🎨 멀린 패밀리 OS - UI/UX 핵심 원칙 총정리

이 문서는 허브 SDK 이외의 UI/UX 관련 디자인 원칙 및 행동 지침을 요약한 문서입니다. 허브 전담 AI가 직접 관리하는 영역(1부)과 개별 패밀리 앱 전담 AI가 자율적으로 적용해야 하는 영역(2부)으로 나뉩니다.

---

# [제 1 부] 허브 전담 AI 통제 구역 (공통 인프라 & 레이아웃)
이 구역의 원칙들은 멀린 패밀리 생태계의 통일성을 위해 **허브 전담 AI가 직접 각 앱의 코드를 수정하여 배포(통제)**합니다. 개별 앱 AI는 이 구조를 임의로 훼손해서는 안 됩니다.

## 1. SSOT (Single Source of Truth) 원칙
- 유저 식별자(UUID)와 계정 정보, 지갑 정보는 오직 **허브 DB(`family_users`)만이 유일한 진실 공급원**입니다.
- 이메일이나 로컬 닉네임 등을 임의의 보조 수단으로 매핑하여 시스템을 우회하거나 어지럽히는 행위는 절대 금지됩니다.

## 2. 반응형 배너 분기 및 고정 위치 원칙 (`HubResponsiveWing`)
패밀리 앱에서 우측에 배치되는 공유 카드 및 파트너 배너 레이아웃은 허브 SDK(`HubResponsiveWing`)에 의해 통제됩니다.
- **[1120px 이상 (PC/태블릿 가로)]**: 우측 빈 공간에 사이드 윙(`aside`) 형태로 고정 배치합니다. 
- **[1120px 미만 (모바일/화면 축소)]**: 우측 윙을 숨기고, 화면 하단 스티키 배너 및 60초 지연 플로팅 버튼(FAB) 기반의 바텀 시트 팝업으로 대체합니다.

## 3. 공통 UI 사전 승인 원칙 (충돌 방지)
- PWA 앱 설치 팝업, 전역 로그인 모달 등은 허브 전담 AI가 통일성 있게 패밀리 앱에 전파할 의무를 가집니다.
- 단, 개별 앱의 고유한 레이아웃이나 기존 기능과 시각적 충돌이 명확히 예상되는 경우, 허브 AI는 코드를 강제 덮어쓰기 전에 **반드시 사장님(멀린)의 사전 승인을 구한 뒤** 안전하게 적용해야 합니다.

## 4. 모바일 반응형(Mobile-First) UI 기초 공사
웹앱(PWA)이 네이티브 앱처럼 동작하도록 다음 뼈대 원칙을 허브 AI가 공통 레이아웃에 주입합니다.
- 하단 스티키 바나 플로팅 버튼(FAB)에 `pb-[env(safe-area-inset-bottom)]` 적용 (기기 하단 간섭 방지).
- 모바일에서 공유 버튼 등 핵심 액션은 1분 지연 노출(Dynamic Nudge)하여 피로도를 낮춤.

# [제 2 부] 개별 앱 전담 AI 자율 수행 구역 (앱 특화 UX)
아래 원칙들은 개별 패밀리 앱(어그로필터, 뭐먹지 등)을 담당하는 AI가 **해당 앱의 특성과 데이터 구조에 맞게 알아서 자율적으로 구현**해야 하는 지침입니다.

## 5. 상호작용 피드백 및 완전성 원칙 (The Click-Link Rule)
- 프로필, 설정, 취소, 메뉴 등 유저가 클릭/터치할 수 있는 **모든 인터랙티브 요소**에는 마우스 호버 시 반드시 손가락 모양 커서가 나오도록 `cursor-pointer` 클래스를 누락 없이 명시해야 합니다.
- **터치 타겟 및 마이크로 인터랙션**: 모든 클릭 가능한 요소는 44px 이상을 권장하며, 눌렀을 때 즉각적인 피드백(`active:scale-[0.98]`, `active:bg-opacity-80`)을 필수 적용합니다. 텍스트 복사가 불필요한 UI에는 `select-none`을 적용합니다.
- 기능이 연결되지 않은 껍데기 UI('먹통' 상태) 노출 금지 (반드시 Alert/Toast로 미구현 안내).

## 6. 더미 데이터 온보딩 (Populated Empty State / Starter Content)
유저가 앱에 처음 진입하여 아무런 데이터가 없을 때(Blank Slate), 텅 빈 화면을 보여주는 것은 최악의 이탈을 유발합니다. 따라서 **유저의 입력이 필요한 모든 주요 페이지에는 반드시 직관적인 '샘플(목업) 데이터'를 미리 채워두어야 합니다.**
- **동작 방식**: 유저가 앱 사용법을 시각적으로 1초 만에 파악할 수 있도록 잘 꾸며진 샘플 카드를 띄워두고, **유저가 실제 데이터를 단 1개라도 입력하는 순간 이 샘플 데이터들은 영구적으로 사라지게(Hide)** 만듭니다.
- **샘플(견본)의 시각적 표시**: 유저가 본인의 데이터로 오인하지 않도록, 앱 담당 AI는 앱의 디자인 성격에 맞춰 다음 두 가지 중 하나의 방식으로 샘플임을 명시해야 합니다.
  - **[A안] 글래스모피즘 리본**: 카드 우측 상단 모서리에 반투명한 대각선 띠(`💡 SAMPLE`)를 두릅니다.
  - **[B안] 하단 페이드아웃 + 툴팁**: 카드 목록의 맨 아래를 그라데이션으로 흐리게 처리(`mask-image: linear-gradient`)하고, "첫 데이터를 입력하면 샘플은 사라져요!" 라는 안내 툴팁을 띄웁니다.
