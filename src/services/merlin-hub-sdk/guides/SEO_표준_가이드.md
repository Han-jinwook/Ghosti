## 🎯 1. 런칭 전 허브 총괄 3대 필수 점검 영역

개별 앱 런칭 전, 허브 총괄 AI는 다음 3대 인프라를 전수 점검하여 배포 무결성을 보장합니다:

1. **📦 SDK 6대 모듈 완전성 검증**: Auth(OTP), Session(30일 롤링 및 SSO), Wallet(과금), Referral(추천), Notification(알림), Ads/UI(800px 레이아웃 & 사이드 윙)

3. **🌐 네이버 & 구글 SEO 파이프라인 완공**: 동적 사이트맵, 로봇 설정, 소유권 인증, 패스트트랙 색인 요청

## 🔍 2. 네이버 & 구글 검색엔진 최적화 (SEO) 표준 규격

### 2.1. 동적 사이트맵 (`sitemap.ts` / `sitemap.xml`)
- **기본 라우트**: 메인 랜딩, 주요 탭 등 정적 페이지 (`priority: 1.0` ~ `0.8`, `changeFrequency: 'daily'`)
- **동적 상세 페이지**: DB에 적재된 콘텐츠 상세 페이지(`priority: 0.6`, `changeFrequency: 'weekly'`)를 자동 수집하여 포함.
- **슬러그(Slug) 규칙**: 한글/영문 제목을 기반으로 정제된 슬러그(`generateSlug`)를 URL 경로에 포함하여 검색 로봇의 키워드 색인 가중치를 극대화.

### 2.2. 로봇 제어 (`robots.ts` / `robots.txt`)
- **검색 로봇 전체 수집 허용**: 네이버 봇(`Yeti`), 구글 봇(`Googlebot`), 다음 봇(`Daum`) 등 주요 크롤러의 일반 페이지 접근 허용 (`Allow: /`).
- **보안/관리자 경로 격리**: 관리자 페이지(`/admin*`), 내부 API(`/api*`) 등은 검색 노출 차단 (`Disallow: /admin`, `Disallow: /api`).
- **사이트맵 링크 명시**: `sitemap: https://[앱도메인]/sitemap.xml` 선언 필수.

### 2.3. 메타데이터 및 검색엔진 소유권 인증
- **소유권 인증 메타태그**:
  - 구글 서치콘솔: `<meta name="google-site-verification" content="..." />`
  - 네이버 서치어드바이저: `<meta name="naver-site-verification" content="..." />`
- **카테고리 킬러 브랜딩 메타태그**:
  - `Title`: `앱이름 | 서브타이틀 (카테고리 킬러 직관적 키워드)`
  - `Description`: 딥리서치 핵심 키워드가 자연스럽게 녹아든 2~3줄 요약 설명
  - `OpenGraph (og:title, og:description, og:image, og:url)` 및 `Twitter Card` 필수 탑재.
- **🖼️ SNS 공유 썸네일(OG Image) 안전 영역 (Safe Zone) 규칙**:
  - 카카오톡/카카오워크/네이버 1:1 및 4:3 썸네일 크롭 시 로고나 텍스트가 좌우로 잘리지 않도록, **중앙 80% 안전 영역(Safe Zone)에 로고를 배치한 정사각형(512x512) 또는 여백형 1200x630 이미지 사용 필수**.
- **💬 카카오톡/카카오워크 인앱 브라우저 PWA 탈출 UX (In-App Escape)**:
  - 인앱 브라우저(WebView) 감지 시: Android는 `intent://` 스키마로 Chrome/삼성인터넷 즉시 실행, iOS는 `Safari로 열기` 툴팁 안내를 지원하여 원활한 PWA 앱 설치 유도.

### 2.4. 패스트트랙 색인 요청 수칙
1. **네이버 서치어드바이저 (NAVER)**:
   - 사이트맵(`sitemap.xml`) 등록 ➡️ **웹페이지 수집 패스트트랙 요청** 실행하여 Yeti 봇의 즉시 수집 유도.
2. **구글 서치콘솔 (GOOGLE)**:
   - 사이트맵 등록 ➡️ **우선순위 색인 생성 대기열(Priority Crawling Queue)** 등록하여 24시간 내 빠른 색인 반영 유도.

## 🧠 3. 키워드 딥리서치 & 이중 점령 전략 (Double Positioning)

### 3.1. 브랜드명 + 카테고리 직관 명칭 이중 방어
- 사용자가 브랜드명을 기억하지 못하더라도 서비스의 역할/기능을 검색하여 유입될 수 있도록 이중 키워드 구조를 수립합니다.
- **포지셔닝 예시**:
  - **리얼픽**: `리얼픽` + `연애프로 시청비서` / `시청도우미` 이중 점령
  - **썬드리머**: `썬드리머` + `썬드림 자외선조사기 회원앱` / `자외선b UVB 비타민d 자연치유 관리` 이중 점령
  - **어그로필터**: `어그로필터` + `유튜브 낚시 감별기` / `유튜브 신뢰도 분석기` 이중 점령

### 3.2. 딥리서치 키워드 풀 구축
- 타겟 유저층이 포털 검색창에서 입력하는 롱테일/핵심 키워드(50~100개)를 발굴하여 메타태그, 본문 텍스트 및 페이지 슬러그에 전략적으로 배치.

## ⚡ 4. [전사 마스터 공통 규칙] 동적 콘텐츠형 앱을 위한 4대 무인 자동화 칙령 (리얼픽 표준)

모든 동적 미디어/콘텐츠형 개별 앱(Next.js SSR/SSG 기반) 및 허브 앱은 다음 4대 핵심 절대 칙령에 따라 100% 무인 자동화 구조로 구현한다.

### 4.1. 🚫 1조: 메인 푸터 무링크 스팸 텍스트(Keyword Stuffing) 완전 금지
- 클릭할 유효 경로(`href`)가 없는 단순 키워드 텍스트 나열은 구글(Googlebot) 및 네이버(Yeti) 알고리즘으로부터 **"키워드 스터핑(저품질 어뷰징 감점)"**을 받으므로 절대 금지한다.
- 클릭이 불가능하거나 서비스하지 않는 미지원 예능/카테고리 텍스트는 푸터에 일절 표기하지 않는다.

### 4.2. 🔗 2조: 메인 푸터 100% 유효 앵커 링크 (Internal Link Juicing) & DB 무인 연동
- 푸터 SEO 키워드는 유저와 크롤링 봇이 실제 방문 가능한 유효 내부 상세 페이지 앵커 링크(`<a>` 또는 `<Link href="...">`) 칩으로 구성한다.
- 키워드를 코드에 하드코딩하지 말고, 데이터베이스(Supabase 등)의 SOT(`status === 'active'` 및 최신 카테고리)와 실시간 연동하여 어드민 셋업 시 수동 작업 0%로 실시간 자동 동기화되도록 만든다.
- **롱테일 조합 공식**: `[카테고리/프로그램명]` + `[기수/시즌명]` + `[상세 기능명 (출연진 프로필 / 선택 흐름표 / 보드 다시보기)]` (예: 나는 솔로 34기 출연진 프로필, 나솔사계 최신 선택표 바로가기)
- **피킹 우선순위**: 현재 라이브 중인 active 콘텐츠 1순위 노출 + 최근 종영 콘텐츠 2개 2순위 자동 배치.

### 4.3. ⚡ 3조: 동적 상세 페이지 동적 메타태그 (`generateMetadata`) 필수 구축
- 기수, 회차, 상품 등 URL 파라미터/슬러그에 따라 콘텐츠가 바뀌는 개별 상세 페이지(예: `/show/[progSlug]/[seasonSlug]`)는 반드시 Next.js Server Component의 **`generateMetadata`**를 사용해 구축한다.
- 상세 페이지 진입 시 DB를 조회하여 해당 기수/시즌 전용 HTML Title, Description, Keywords를 실시간으로 생성하여 주입한다.
  - *Title 예시*: `나는 솔로 33기 출연진 프로필 & 선택 흐름표 | 리얼픽`
  - *Description 예시*: `나는 솔로 33기 전 출연진 얼굴, 직업, 인스타 정보와 회차별 화살표 선택 결과를 확인하세요.`

### 4.4. 🖼️ 4조: 카카오톡/SNS 공유 메타 (OpenGraph) & 중복 색인 방지 (Canonical)
- 동적 메타태그 세팅 시 카카오톡이나 SNS에 공유되었을 때 깔끔한 썸네일 카드가 뜨도록 `openGraph` (`og:title`, `og:description`, `og:image`, `og:url`) 및 `twitter` 메타데이터를 해당 기수의 전용 로고/이미지로 동적 연결한다.
- `alternates.canonical`에 해당 상세 페이지의 고유 정식 URL을 명시하여 검색엔진의 파라미터 중복 색인 오인을 차단한다.
