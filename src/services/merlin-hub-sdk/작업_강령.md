# 🛡️ 안티그래비티 작업 강령 (Antigravity's SOP)

본 문서는 멀린 패밀리 OS와 허브 SDK를 관리하는 AI 개발자 '안티그래비티'가 반드시 준수해야 할 **작업 절대 원칙**입니다. 사장님의 지시 없이도 이 규칙은 모든 작업의 최우선 순위를 가집니다.

---

## 🚨 1. 원본 동기화의 원칙 (The Source-First Rule)
- 개별 앱(어그로필터, 루미노트 등) 연동 중 SDK 버그나 개선사항이 발견될 경우, 해당 프로젝트만 수정하고 끝내지 않는다.
- **수정 순서**:
  1. `MerlinFamilyOS/허브_라이브러리/` 원본 소스 수정
  2. `라이브러리_활용가이드.md` 및 `라이브러리_대장.md` 업데이트
  3. 개별 앱 프로젝트에 반영 (이때, 가이드 문서들도 함께 최신본으로 동기화한다)
  4. 복사/반영한 일시와 버전을 허브의 `라이브러리_대장.md` 대출 현황 장부에 즉시 기록한다.
- **이유**: 원본을 고치지 않으면 다음 앱 연동 시 똑같은 버그를 재발산하게 되며, 이력을 남겨야 패밀리 전체의 버전을 통제할 수 있다.

## 🏗️ 2. 빌드 안정화 및 엔트리 관리 (Dual Entry Strategy)
- Next.js의 서버 사이드 렌더링 에러를 방지하기 위해 SDK 입구를 항상 이원화한다.
- `index.ts`: 서버/클라이언트 공용 (Hook/UI 포함 금지)
- `react.ts`: 클라이언트 전용 (Hooks, UI 컴포넌트 전용)
- 모든 UI 컴포넌트 상단에는 반드시 `'use client';` 지시어를 명시한다.

## 🔍 3. 데이터 검증의 엄격성 (The Success-Check Rule)
- API 호출 결과 객체가 존재한다고 해서 성공으로 간주하지 않는다.
- 반드시 `if (result && result.success === true)` 처럼 명시적으로 성공 여부를 확인한다.
- 특히 세션 체크(`useHubSession`)와 결제 처리에서 이 규칙을 어길 시 시스템 전체가 기만적 상태에 빠질 수 있다.

## 🖱️ 4. UI 상호작용의 완전성 (The Click-Link Rule)
- 커스텀 위젯(예: `HubProfileWidget`)을 페이지에 배치할 때는, 해당 부품이 제공하는 콜백 프로퍼티를 반드시 실제 기능(모달 오픈, 페이지 이동 등)과 연결한다.
- **먹통 방지**: 기능이 연결되지 않은 UI는 유저에게 불쾌한 경험을 주므로 절대 금지한다.

## 📜 5. 선 확인 후 작업 (Check Before Action)
- 모든 작업 시작 시, `라이브러리_대장.md`를 가장 먼저 확인하여 최신 버전과 에코시스템의 현황을 파악한다.
- 사장님이 일일이 가이드하지 않아도, 장부의 기록을 통해 스스로 다음 할 일을 도출한다.

## ✍️ 6. 상호 격리 및 침범 절대 금지의 원칙 (The Strict Isolation Rule)
- **개별 앱 AI의 허브 침범 및 자체 해결 절대 금지**: 개별 패밀리 앱을 전담하는 AI는 어떠한 경우에도 `MerlinFamilyOS`(허브 본진) 저장소의 코드를 직접 수정하거나 커밋/푸시해서는 안 되며, 심지어 **자신들의 앱 내부에 있는 허브 SDK 연동부(1부/2부)에 문제가 생겼을 때도 임의로 수정해서는 안 됩니다.**
- **버그 발견 시 토스 의무**: 개별 앱 개발 중 허브 연동과 관련된 버그나 오류, 혹은 개선점이 발견될 경우, 개별 앱 AI는 직접 코드를 만지지 말고 **반드시 "오류 보고서"를 작성하여 사장님(멀린)을 통해 허브 전담 AI(안티그래비티)에게 토스**해야 합니다. 허브 원본 및 개별 앱의 허브 연동부 수정은 오직 사장님의 지시를 받은 허브 전담 AI만이 전적으로 수행합니다.

---
## 📦 7. 허브 SDK 배포 및 전파 전략 (SDK & Docs Distribution)
- **가이드 문서 전면 배포**: 개별 앱 전담 AI가 코드를 직접 만지지는 않더라도, 허브의 전체 작동 흐름과 규격을 명확히 이해해야 합니다. 따라서 허브 SDK를 개별 앱에 동기화할 때는 SDK 코드뿐만 아니라 `라이브러리_활용가이드.md`, `라이브러리_대장.md`, `작업_강령.md` 등 **모든 가이드 문서와 폴더 내 .md 파일들을 빠짐없이 함께 배포**하여 한곳에 모아두어야 합니다.
- **End-to-End 연동 (허브 AI 100% 책임제)**: 개별 앱 연동 시, 허브 전담 AI가 개별 앱 저장소에 진입하여 다음의 1부와 2부 작업을 전적으로 책임지고 끝까지 완수합니다.
  1. **1부 (기초 인프라)**: `src/services/merlin-hub-sdk` 주입, 로그인 모달 및 프로필 위젯 바인딩, 공통 헤더 및 PWA 규격 적용.
  2. **2부 (개별 앱 UX 고도화)**: 상호작용 커서 피드백(버튼 애니메이션 등) 적용, 빈 화면 방지용 샘플/더미 데이터 등 UI 가이드라인의 세부 사항까지 허브 AI가 직접 개별 앱 코드베이스를 분석하여 완벽하게 깎고 다듬습니다.

## 🌐 8. 인프라 배포 환경 (Infrastructure Topology)
패밀리 앱 에코시스템은 용도에 따라 다음과 같이 배포 플랫폼이 통제됩니다. (🚨 절대 혼동 금지)
- **🏰 허브 본진 (`MerlinFamilyOS` / `os.sundreamer.app`)**: **Render** (Node.js 백엔드 + 관리자 대시보드)
- **🌐 나머지 모든 패밀리 앱 (`썬드리머/LumiNote`, `어그로필터`, `뭐먹지`, `리얼픽`, `Bes2`, `볼트`, `센스톡`, `오토노트` 등 전체)**: **Netlify Pro** (프론트엔드 + 정적/SPA 배포 최적화)

## 🚀 9. 개별 앱 허브 인프라 '원샷(One-Shot) 10단계 표준 시공 프로토콜' (Piecemeal Deployment Zero Rule)
- **철칙**: 멀린님이 **"이 앱에 허브 인프라 깔아라"**라고 지시하면, 하나씩 찔끔찔끔 적용하다가 멀린님이 지적할 때마다 땜빵하는 행위를 **절대 엄금**한다. 반드시 아래 **10단계 표준 시공 순서도**를 단 한 번의 호흡으로 전수 점검·시공·검증하여 한 번에 완결 보고해야 한다.

1. **[STEP 1] 허브 백엔드(`MerlinFamilyOS`) 앱 등록 및 CORS 개방**
   - `src/services/auth.service.ts`, `src/services/wallet.service.ts`에 공식 `appId`(예: `SenseTalk`) 및 과금/무료 정책 등록
   - `src/server.ts` CORS 화이트리스트에 개별 앱 도메인 등록
2. **[STEP 2] 허브 SDK 원본(`허브_라이브러리/*`) 및 가이드 문서(`.md`) 전수 복사**
   - 개별 앱의 `src/services/merlin-hub-sdk/` 경로에 `Auth`, `Session`, `Wallet`, `Referral`, `Notification`, `Support`, `CoreLogic`, `SharedUI`, `assets` 및 모든 `.md` 가이드를 100% 동일하게 복사하고 `라이브러리_대장.md` 대출 현황 장부에 즉시 기록
3. **[STEP 3] HTML 루트 보호 및 인앱 브라우저 탈출 가드 (`CoreLogic` / `HubProvider` v2.9.0)**
   - `<html lang="ko" class="notranslate" translate="no">` 및 `<meta name="google" content="notranslate" />` 필수 삽입
   - 카카오톡/네이버/인스타/라인 인앱 브라우저 진입 시 0.1초 안드로이드 크롬 외부 브라우저 자동 탈출(`intent://`) 탑재
   - URL 파라미터 `?sso_token=`, `?token=`, `?openGift=1`/`#giftbox`(선물함 자동 오픈) 및 멀티 탭 `focus`/`storage` 실시간 동기화 리스너 탑재
4. **[STEP 4] 헤더 우측 허브 트윈 위젯 (`HubAppSwitcher` v2.16.0 + `HubProfileWidget` v1.3)**
   - 패밀리 스위처(`F` 로고, 가입 앱 상태 표시 및 `?sso_token=` 무로그인 핸드오프)
   - 3D 곰발바닥 프로필 위젯(게스트: 곰발바닥 아이콘 + `'게스트'` / 로그인: 곰발바닥 배경 위 음각 이니셜 + 닉네임)
5. **[STEP 5] 표준 OTP 로그인 모달 (`HubAuthModal` v2.1.1 — 썬드리머 외 전 앱 단일 표준)**
   - `appName !== '썬드리머'`인 모든 패밀리 앱은 `f9748f8` 순정 표준(`placeholder="이메일 주소 입력 (example@email.com)"`, 5,000P 문구/네이버 전용 안내 0건, 최근 로그인 계정 X 삭제 칩, 6자리 OTP 자동 포커스/붙여넣기)을 100% 그대로 적용
6. **[STEP 6] 통합 프로필 설정 모달 (`HubProfileCards` v2.4.0)**
   - 닉네임 즉시 수정(`PATCH /api/user/profile`), 내 잔여 코인 표시, 내 선물함(`[새 선물 N개!]` 실시간 배지) & 선물하기 진입 버튼, 이메일 알림 수신 토글(`PATCH /api/user/notification`), 다른 계정으로 전환, 로그아웃 카드 완비
7. **[STEP 7] 패밀리 선물함 & 코인 선물하기 (`HubGiftBoxModal` v2.1.0)**
   - 균등 3탭(`📥 받은 선물` 미수령 상단 하이라이트 & `[🎁 선물 열기]` / `📤 보낸 선물` `[🔔 알림 재전송]` & `[↩️ 선물 취소]` / `🎁 선물 보내기` STEP 1 상품·자유금액 + STEP 2 `[👥 내 지인 선택 ▾]` 및 미완성 한글 자모 방어 220ms 실시간 회원 검색 + STEP 3 응원 테마 4종) 완비
8. **[STEP 8] 우측 공유 날개·모바일 플로팅 구슬·`?ref=` 추천코드 영구 폐지 & 통합 CS 문의방·블랙박스(`Support` v1.0.0)**
   - **전사 공유 정책 (v2.19.0)**: PC 우측 사이드 공유 카드(`HubShareSquare`), 모바일 1분 플로팅 원형 구슬(FAB), `?ref=` 추천인 코드 및 친구 초대 모달은 전 패밀리 앱에서 영구 폐지한다. 일반 링크 공유는 오직 PC(`hidden lg:flex`) 우상단 표준 공유 아이콘 클릭 시 **순수 URL 1클릭 클립보드 복사 + 토스트(A안)**만 허용하며, 모바일에서는 일반 공유 버튼을 일체 두지 않고 **100% 각 앱의 고유 기능 맥락 기반 초대/공유**만 사용한다.
   - 프로필 모달 하단 `1:1 고객문의 · 나의 문의방`(`studio.sundreamer.app/support` 연동 + `[새 답변 N건 도착!]` 실시간 배지) 및 `🐞 1초 오류 · 불편 즉시 신고`(최근 20개 클릭·에러 브레드크럼 블랙박스 자동 동봉) 탑재
9. **[STEP 9] 비로그인 게스트(신입) 코인 오염 차단 & 허브 표준 샘플 띠(`💡 SAMPLE`) 온보딩 (`개별앱_UI_UX가이드2.md` 제6조)**
   - 비로그인 게스트 상태에서 과거 로컬 캐시로 인한 코인/유료 쿼터 오표시 원천 차단(`0 C` 고정)
   - 초기 게스트 화면의 샘플 데이터 영역(테이블 및 블록/메모 박스) 우측 상단에 노란 대각선 리본(`💡 SAMPLE`) 및 하단 안내 띠(`💡 SAMPLE 첫 데이터를 입력하면 샘플은 사라져요!`)를 두르고, 첫 타이핑/추가 즉시 샘플 띠가 실시간 소멸되도록 구현
10. **[STEP 10] 개별 앱 전용 Supabase RLS 격리(`user_id`) 및 SSOT 매핑**
    - 모든 유저 자산 테이블을 허브 `family_users.id`(`user_id`) 기준으로 완벽 격리
    - 코인·결제 원장은 허브 중앙 DB에서만 관리하며, 개별 앱에는 로컬 무인 DB 백업 워크플로우(`daily-db-backup.yml`)를 별도 구축하지 않음
