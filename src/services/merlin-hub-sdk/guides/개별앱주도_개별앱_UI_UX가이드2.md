# [제 2 부] 개별 앱 전담 AI 자율 수행 구역 (앱 특화 UX)

아래 원칙들은 개별 패밀리 앱(어그로필터, 뭐먹지 등)을 담당하는 AI가 **해당 앱의 특성과 데이터 구조에 맞게 알아서 자율적으로 구현**해야 하는 지침입니다.

## 5. 상호작용 피드백 및 완전성 원칙 (The Click-Link Rule)
- 프로필, 설정, 취소, 메뉴 등 유저가 클릭/터치할 수 있는 **모든 인터랙티브 요소**에는 마우스 호버 시 반드시 손가락 모양 커서가 나오도록 `cursor-pointer` 클래스를 누락 없이 명시해야 합니다.
- **터치 타겟 및 마이크로 인터랙션**: 모든 클릭 가능한 요소는 44px 이상을 권장하며, 눌렀을 때 즉각적인 피드백(`active:scale-[0.98]`, `active:bg-opacity-80`)을 필수 적용합니다. 텍스트 복사가 불필요한 UI에는 `select-none`을 적용합니다.
- 기능이 연결되지 않은 껍데기 UI('먹통' 상태) 노출 금지 (반드시 Alert/Toast로 미구현 안내).

## 6. 더미 메모 온보딩 (Populated Empty State / Starter Content)
유저가 앱에 처음 진입하여 아무런 데이터가 없을 때(Blank Slate), 텅 빈 화면을 보여주는 것은 최악의 이탈을 유발합니다. 따라서 **조회 전용 페이지가 아닌, 등록(입력) 섹션이 존재하는 모든 페이지에는 무조건 페이지 특성에 맞는 '샘플(목업) 데이터'를 1개씩 만들어두어야 합니다.**
- **동작 방식**: 유저가 앱 사용법을 시각적으로 단번에 파악할 수 있도록 샘플을 노출해두고, **해당 페이지에서 유저가 실제 데이터를 단 1개라도 등록하는 순간 그 페이지의 샘플 데이터는 즉시 수거(영구 Hide)하는 개념**입니다. 전체 데이터가 아닌 철저히 '해당 페이지' 단위로 수거가 이루어져야 합니다.
- **샘플(견본)의 시각적 표시**: 유저가 본인의 데이터로 오인하지 않도록, 앱 담당 AI는 앱의 디자인 성격에 맞춰 다음 두 가지 중 하나의 방식으로 샘플임을 명시해야 합니다.
  - **[A안] 글래스모피즘 리본**: 카드 우측 상단 모서리에 반투명한 대각선 띠(`💡 SAMPLE`)를 두릅니다.
  - **[B안] 하단 페이드아웃 + 툴팁**: 카드 목록의 맨 아래를 그라데이션으로 흐리게 처리(`mask-image: linear-gradient`)하고, "첫 데이터를 입력하면 샘플은 사라져요!" 라는 안내 툴팁을 띄웁니다.

## 7. 모바일 폼 및 숫자 입력창 UX 표준 규격 (Mobile Input & Back-Cursor Rule)
모바일 브라우저에서 숫자, 금액, 수량, 인증번호 입력 시 유저가 겪는 커서 오동작 및 키패드 불편을 원천 방지하기 위해 다음 5대 폼 표준을 준수합니다.

1. **스마트 키패드 & 스핀 버튼 제거 (`inputMode`)**:
   - `type="number"`의 불필요한 증감 화살표(스핀 버튼)와 브라우저별 커서 제약 에러를 피하기 위해, 정수 입력은 `type="text" inputMode="numeric" pattern="[0-9]*"`, 소수점/실수 입력은 `inputMode="decimal"`을 표준으로 사용합니다.
2. **커서 맨 뒤 자동 위치 (Back-Cursor Focus)**:
   - 모바일에서 입력된 기존 숫자를 수정하려고 재터치했을 때 커서가 앞쪽에 걸려 백스페이스(⌫)가 먹통이 되는 현상을 방어하기 위해, SDK 공통 헬퍼인 `handleCursorToEnd`를 `onFocus` 및 `onClick`에 기본 바인딩합니다.
   ```tsx
   import { handleCursorToEnd } from '@/src/services/merlin-hub-sdk/react';

   <input
     type="text"
     inputMode="numeric"
     value={count}
     onFocus={handleCursorToEnd}
     onClick={handleCursorToEnd}
     onChange={(e) => setCount(e.target.value.replace(/[^0-9]/g, ''))}
   />
   ```
3. **인증번호 원터치 자동완성 (`autoComplete="one-time-code"`)**:
   - 6자리 OTP, 문자 인증번호 입력 필드에는 반드시 `autoComplete="one-time-code"`를 지정하여 모바일 키보드 상단 칩을 통한 1초 원터치 완성을 보장합니다.
4. **마이크로 햅틱 피드백 (`triggerHaptic`)**:
   - 폼 입력 완료, 저장 성공, 복사 성공 시 SDK의 `triggerHaptic('light' | 'success')`를 호출하여 네이티브 앱 감성의 가벼운 진동을 제공합니다.

## 8. 검색 UI 최근 검색어(Recent Searches) 및 Zero-Clutter 표준 규격 (모든 앱 디폴트)
사용자가 데이터를 탐색하는 모든 검색 입력창(상품, 부품, 주문, 게시글, 메뉴, 영상 등)은 유저의 반복 검색 피로를 줄이고 모바일/PC 화면 공간을 극대화하기 위해 다음 규격을 디폴트로 적용합니다.

1. **군더더기 텍스트 완전 배제 (Zero-Clutter)**:
   - 검색창 하단에 "검색 결과: 'OOO' (N건)", "검색 초기화" 같은 불필요한 보조 안내선과 여백 낭비 버튼을 나열하지 않습니다.
   - 검색어 확인 및 리셋은 검색 입력창 내부의 텍스트 값 및 우측의 깔끔한 인라인 삭제(`✕`) 버튼 하나로 심플하게 해결합니다.
2. **최근 검색어(Recent Searches) 로컬 자동 영구 누적**:
   - 사용자가 검색창에 검색어를 입력하고 실행(Enter, 선택, focus out 등)하면 `localStorage`에 최근 검색어(최대 6~10개)를 중복 없이 최신순(선두)으로 자동 누적 보관합니다.
3. **입력창 클릭/포커스 시 플로팅 드롭다운 연동**:
   - 검색창 클릭/포커스(`onFocus`) 시 입력창 바로 아래에 플로팅 드롭다운(`absolute z-30`)으로 ⏱️ 최근 검색어 칩 목록이 매끄럽게 딸려나옵니다.
   - **원터치 재검색**: 칩 터치 1번으로 즉시 해당 검색어가 입력창에 주입되고 검색이 실행됩니다.
   - **간결한 관리**: 각 검색어 칩 우측에 개별 삭제(`✕`) 버튼을 제공하고, 드롭다운 우측 상단 또는 하단에 `전체삭제` 버튼을 배치합니다.
   - **자연스러운 닫힘**: 외부 영역 터치/클릭(`onBlur` 또는 바깥 클릭 감지) 시 드롭다운이 자연스럽게 닫히도록 처리합니다.
4. **모바일 가상 키패드 호환 방어**:
   - 모바일 키보드가 올라온 상태에서도 결과 목록이나 드롭다운이 화면을 가리거나 깨지지 않도록 `max-h-48 overflow-y-auto` 및 명확한 `z-index` 계층을 방어합니다.
